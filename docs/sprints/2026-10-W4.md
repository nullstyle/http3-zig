# Sprint 2026-10-W4: whole-frame writes

Chosen 2026-10-09 (the owner's option 1: move cluster B to quic v0.38.0,
then this fix). Tasks live here, not in GitHub issues.

## Why this sprint

Session writes an HTTP/3 frame as a header and then a payload, with one
`quic.Connection.streamWrite` call each. quic can take fewer bytes than
offered: the stream's send buffer is full, or the connection's memory
budget is (quic v0.38.0 gives the writer half the budget, 16 MiB by
default, so this comes sooner). Session then returned `WriteStalled`,
and the cut frame was already on the wire: the peer saw a malformed
stream. quic's `SendWindow` counts only flow-control credit, so an
embedder that checked it could still hit this.

## Rules

- Red first: a test that forces the short write must fail before the fix.
- Every gate before a push: core, cross (6 targets x 2 modes), interop,
  bench, both smoke tests.
- No release without the user. The release (v0.5.7) pairs with
  capnp-zig v0.25.0 on quic v0.38.0.
