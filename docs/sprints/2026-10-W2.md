# Sprint 2026-10-W2: real-socket bench tier

Chosen 2026-10-05 (option B of the 2026-10-04 plan), after v0.5.1.
Tasks live here, not in GitHub issues.

## Why this sprint

Every http3-zig benchmark today runs in one process over an in-memory
shim: no sockets, no kernel, and a handshake that skips the packet
path. That shim hid two real things this month: the BoringSSL
packet-key leak that quic v0.21.1 fixed (its code path never ran in our
benches), and a test server that served one QUIC connection (Firefox
needs two). A real-socket tier measures what users run.

## Rules

- Real UDP sockets on loopback, real `quic.Server` / client loops.
- A CI gate checks numbers that are stable on a shared runner: counts
  (allocations, datagrams, bytes per request) and memory slopes. Wall
  time is reported, not gated, or gated only with a wide margin.
  quic-zig measured about 5% wall-time movement from code layout alone.
- Every gate is ablated: show it fails on a seeded fault before it is
  trusted.
- Commit per green step. Full local battery before each push. The user
  approves every tag.

## Tasks

### B1. `bench-e2e`: real-socket HTTP/3 and WebTransport cells

- [x] `bench/e2e.zig` (`zig build bench-e2e`): server thread on
      `quic.Server`, real clients on the main thread, JSON report
      (`f453d94`).
- [x] Cells `h3_connect` and `h3_get` with p50/p99 and per-op
      allocations, packets and bytes. Allocation counts are identical
      on macOS and Linux (74/88 per connection, 17/22 per GET).
- [x] WT cells `wt_session`, `wt_datagram`, `wt_uni` over real
      sockets (`9d23670`). They found two leaks:
      - A finished WT substream kept its state for the connection's
        life (~250 bytes; a session stopped after ~1000 uni streams).
        Fixed in `4fc9d01`.
      - A loop that does handle, `tick`, drain can lose a bare FIN:
        quic's `tick` stream GC reaps the stream first (392.7 bytes
        per WT session). The guide and interop clients now drain
        before `tick` (`6e624ce`). Handoff for quic-zig:
        `docs/upstream/quic-stream-gc-bare-fin.md` (sent 2026-10-05).
- [x] Linux baseline WT entries from the CI artifact (run on `dea48e5`).

### B2. Many-handshake memory soak

- [x] Soak cell: malloc in-use bytes after the server reaps every
      connection, slope over the second of two phases. macOS 0.0,
      Linux 3.1 bytes/connection. RSS is not usable (allocator page
      retention, 10-40 KB/connection with no leak).
- [x] Ablated: `--seed-leak 64` reads exactly 64.0 and fails the gate.
      (First try read 0.0: ReleaseSafe deleted the unused malloc.)

### B3. Baselines and a compare tool

- [x] Built into the bench: `--check bench/baselines/e2e-<os>.json`
      (`61cf7aa`); `just bench-e2e`. Tolerances in
      `bench/baselines/README.md`.
- [x] CI gates Linux on every push and uploads the JSON. First gated
      run: PASS.
- [x] Found with the new tier: `examples/udp_server.zig` kept every
      request it served (377 bytes per request on an open connection).
      New `ServerRunner.release` / `ClientRunner.release` (and tracker
      `release`); the example uses it; the gate checks retained bytes
      per request (`--server-keep-requests` ablation fails it).

### B4. Docs

- [x] `docs/perf-baseline.md` and `docs/memory-profile.md` have the
      real-socket numbers; the embedding guide says to release runner
      state.

## Not in this sprint

- Impairment (loss, delay) cells. They need virtual time or `tc netem`;
  quic-zig already measures the transport under impairment.
- Dynamic-QPACK default flip, Expect: 100-continue, ngtcp2/lsquic peers.
