# Sprint 2026-10-W1: honest gates, then ship

Chosen 2026-10-04 (option A of two; option B, the real-socket bench
tier, is the next candidate). Tasks live here, not in GitHub issues.

## Why this sprint

The nightly fuzz job showed green for 30 nights while it crashed a
minute into every run (fixed in `73f18ac` / `300e934`). A gate that
can be green while it tests nothing is worse than no gate. Before the
next feature, every gate must prove that it did its work.

## Rules

- A gate is honest when "green" means "the work ran and passed". It
  must fail when it ran zero tests, skipped every peer, or stopped
  early.
- Read step logs, not job colors. A step with `continue-on-error`
  shows "success" even when it fails.
- Commit per green step. Full local battery before each push. The
  user approves every tag.

### A1. Audit every gate for "green but did nothing"

For each workflow, write down what green proves, then add the missing
assertion. Known items:

- [ ] `interop/external_h3/run_matrix.sh` exits 0 with `passed=0` when
      every peer is skipped (a missing `*_H3_SERVER_CMD` skips a peer).
      The gating quic-go leg must require `passed >= 1`.
- [ ] `wt-interop-matrix` exits 0 when one target passes and others
      fail. The advisory step must report each failed peer as an
      annotation (audit finding F17).
- [ ] `fuzz-nightly.yml`: no check that the fuzzer had coverage. Add a
      floor (the run must report non-zero coverage), or a bounded
      `--fuzz=N` run that exits normally and prints its stats.
- [ ] `fuzz.yml` corpus walk: fail when a target has zero cases.
- [ ] Test-count floor: fail `zig build test` in CI when the total
      drops below a recorded floor (guards a test file that silently
      stops being imported).
- [ ] Record the audit result as a table in this file (workflow, what
      green proves, assertion added).
