# Sprint 2026-10-W1: honest gates, then ship

Chosen 2026-10-04 (option A of two; option B, the real-socket bench
tier, is the next candidate). Tasks live here, not in GitHub issues.

## Why this sprint

The nightly fuzz job showed green for 30 nights while it crashed a
minute into every run (fixed in `73f18ac` / `300e934`). A gate that
can be green while it tests nothing is worse than no gate. Before the
next feature, every gate must prove that it did its work.

## Rules

- A gate is honest when "green" means "the work ran and passed". It
  must fail when it ran zero tests, skipped every peer, or stopped
  early.
- Read step logs, not job colors. A step with `continue-on-error`
  shows "success" even when it fails.
- Commit per green step. Full local battery before each push. The
  user approves every tag.

### A3. Run Firefox for real

- [x] First real runs. Found and fixed, one at a time:
      1. TLS alert 42: the test cert was a self-signed CA cert, which
         Firefox refuses as a server cert. Now a CA-signed leaf
         (`26c0eea`).
      2. Firefox turns HTTP/3 off for a non-built-in root CA
         (`hasThirdPartyRoots=1`). Pref set in the test profile
         (`24daf74`), as web-platform-tests does.
      3. Firefox opens two QUIC connections to the server.
         `interop/external_wt/server.zig` served one connection and
         re-aimed replies at the last datagram's sender, so both broke.
         The server now runs on `quic.Server` (`e5c6373`); the test
         clients pick random connection IDs; a new gate
         (`two_clients.sh`, third leg of wt-interop-self-test) runs two
         clients at once (the old server fails it).
- [x] Firefox PASS twice in a row (37273251146, 37273727252): the first
      real Firefox WebTransport sessions against http3-zig. Then two
      green push runs (37274271134, 37276086898): promoted to a hard
      gate.
- [x] Found on the way: the WT test client never sent its
      CLOSE_WEBTRANSPORT_SESSION. It stopped the loop the moment it
      queued the capsule and printed "close all flushed", so no peer
      (ours, webtransport-go, pywebtransport) ever got it, and the
      close phase was never tested. It now waits for proof: the peer's
      transport ACK of the whole CONNECT stream, or a clean connection
      close after our CLOSE. Our server now logs `how=close_capsule`.

### A5. Small fix: GREASE stream at session start

- [x] Done in `63338f8`. `Session.start` opens the GREASE uni stream unconditionally. A

      best-effort. Test with a uni window of exactly the required
      streams.
